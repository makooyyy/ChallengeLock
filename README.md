Фан-генератор челленджей для Deadlock: рулетка героя и условий, случайный билд под бюджет, запрет на следующий матч и история контрактов. Чистые HTML/CSS/JS (ES-модули), без сборки, без бэкенда, с полным офлайн-режимом.

**Сайт:** <https://makooyyy.github.io/ChallengeLock/>

> Фан-проект, не связан с Valve. Deadlock — торговая марка Valve.

## Возможности

| Раздел         | Что делает                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Рулетка        | Герой + 1–3 условия по выбранной сложности, замки на отдельных слотах, перебросы, «Вызов дня»                                            |
| Режимы         | Уличная стычка, обычный и рейтинговый наборы заданий; режим сохраняется в ссылке и истории                                               |
| Сложность      | Лёгкая, обычная, сложная, безумие — без очков, множителей и рангов                                                                       |
| Билд           | Экспериментальный генератор: этапы лайн/середина/вся игра, точный бюджет, ветки, лимит активных предметов, закрепление и отметки покупок |
| Запрет         | Добровольное правило на следующий матч: герой, слот способности, запрет ультимейта или предмета из своего билда                          |
| Экспорт в игру | Код сборки для вставки в Deadlock (Base64 + zstd + protobuf), при желании вместе с текстом челленджа                                     |
| История        | Завершённые и проваленные контракты, избранное, ручная отметка результата, таймер матча                                                  |
| Обновления     | Дневник версий сайта и текущий номер сборки; ссылка — в подвале, рядом с копирайтом                                                      |
| Интерфейс      | Светлая и тёмная темы, RU/EN, клавиатурная навигация, `prefers-reduced-motion`, мобильная вёрстка                                        |
| PWA            | Устанавливается на телефон, работает офлайн за счёт Service Worker                                                                       |

Названия героев намеренно остаются на английском: это имена собственные из игры. Локализуются подписи интерфейса и тексты заданий.

## Локальный запуск

Приложению нужен HTTP-сервер: ES-модули и `fetch` не работают с `file://`.

```sh
python3 -m http.server            # или: npx serve .
```

Откройте <http://localhost:8000>.

## Десктопная версия

В `desktop/` лежит Electron-обёртка: она поднимает локальный HTTP-сервер над этой же папкой и открывает сайт в отдельном окне. Сборка необязательна для веба и в деплой на Pages не входит.

```sh
cd desktop
npm install
npm start        # запуск
npm run build    # portable .exe в desktop/dist
```

Подробности — в [desktop/README.md](desktop/README.md).

## Данные и точность

Каталог получен из [Deadlock API](https://deadlock-api.com/): версия клиента **6861**, **42 доступных героя** и **156 предметов** T1–T4. Оба файла загружаются для одной зафиксированной версии через `/v1/assets/heroes` и `/v1/assets/items` на `https://api.deadlock-api.com`. Документация: <https://api.deadlock-api.com/docs>, схема: <https://api.deadlock-api.com/openapi.json>.

В `_meta` записаны версия клиента, дата получения, адрес запроса, SHA-256 ответа и общая ревизия каталога. `verified: true` означает соответствие полученному снимку API, а не независимую проверку Valve и не обещание вечной актуальности. Челленджи остаются авторскими правилами, их выполнимость API не проверяет.

В генерацию попадают только герои `player_selectable && !disabled && !in_development` и предметы `type=upgrade`, `shopable`, не отключённые, уровней 1–4. Служебные способности/оружие и специальные T5 исключены из обычных билдов. Генератор не выдаёт одновременно предмет и его компонент, поэтому их стоимость не считается дважды. Оптимизация промежуточных покупок не выполняется: это случайный набор конечных предметов.

Внутренние строковые ID сохранены, API ID записаны в `apiId`. Удалённые записи остаются с `active: false` для истории и больше не выпадают.

### Обновление каталога

Нужен Node.js 22+ и доступ к публичному API, ключ не требуется:

```sh
npm run check:catalog   # показать изменения без записи
npm run sync:catalog    # обновить data/*.json и CATALOG_VERSION в sw.js
npm test
```

Скрипт определяет последнюю версию клиента, получает каталоги именно для неё, проверяет структуру, полноту, ID и граф компонентов. Ошибка API или валидации оставляет последний рабочий каталог, ошибки записи откатываются, необычно большое сокращение каталога останавливает обновление. При отсутствии изменений файлы не переписываются. Публикуйте JSON и `sw.js` вместе.

Для воспроизводимой проверки скачанного снимка есть `--input-dir DIR`: нужны `api-versions.json`, `api-heroes.json`, `api-items.json` и `snapshot.json` с `clientVersion`.

## Генерация и ссылки

- Детерминизм: `seed` + сложность + номер переброса + замки полностью определяют результат; число условий считается отдельным потоком RNG, поэтому повторный бросок без замков и прямое восстановление совпадают.
- Ссылка `#v=2&seed=…&d=…&r=…&p=…&x=…` воспроизводит героя, условия и настройки генерации у получателя. Ссылки из истории и избранного используют тот же формат.
- Старые ссылки `#seed=abc&d=mid&r=0&p=2` открываются с настройками по умолчанию.
- Неудачная генерация не расходует попытку; локально сохраняются только результаты выполнения и провала.
- «Вызов дня» считается по локальной дате игрока и меняется в его полночь.

## Как добавить челлендж

В `data/challenges.json` добавьте объект:

```json
{
  "id": "team_hold_high_ground",
  "cat": "tm",
  "difficulty": 3,
  "name": { "ru": "…", "en": "…" },
  "desc": { "ru": "…", "en": "…" },
  "tags": ["team"],
  "conflicts": ["solo_only"],
  "heroes": "all",
  "mode": "team",
  "gameModes": ["normal", "ranked"]
}
```

`cat` — одна из `ab`, `it`, `gp`, `go`, `tm`, `ch`. `difficulty` — 1–5. `mode` — `solo` или `team`. `gameModes` опускается для старых заданий (считаются обычным режимом). Конфликт: A и B не выпадут вместе, если у одного в `conflicts` есть тег другого. Поле `heroes` принимает `"all"` или массив ID и зарезервировано под задания для конкретного героя — сейчас все задания общие.

## Состояние в браузере

Единственный ключ `dlr.v1` (настройки, история, избранное, билд, запрет). При загрузке состояние нормализуется и чистится, повреждённые записи отбрасываются. Таймер матча хранится отдельно в `dlr.timer` и переживает перезагрузку. Приватный режим и переполнение квоты не ломают интерфейс — сохранение просто не происходит.

## Версия и дневник обновлений

Версия сайта живёт в `data/changelog.json`: первая запись массива `releases` — текущая. Из неё берутся подпись `vX.Y.Z` в подвале и страница «Обновления». Формат записи:

```json
{
  "version": "1.17.0",
  "date": "2026-11-18",
  "title": { "ru": "…", "en": "…" },
  "items": { "ru": ["…"], "en": ["…"] }
}
```

Записи идут от новых к старым, у каждой есть оба языка и одинаковое число пунктов. Это проверяет `tests/changelog.test.js`. Технический счётчик `vN` в `sw.js` — отдельная сущность: он отвечает только за инвалидацию офлайн-кэша. Пользовательские заметки пишите в `data/changelog.json`, подробную техническую историю — в `CHANGELOG.md`.

## Проверки

Нужен Node.js 22+.

```sh
npm test                # unit-тесты: 2000 комбинаций seed/сложности, схемы, дневник обновлений, изоляция кэшей
npm run check:sw        # каждый файл в кэше sw.js и версия кэша обновлена
npm run format:check    # Prettier
npm run check           # всё перечисленное
```

Дополнительно — настоящий браузер:

```sh
npm install --no-save playwright
npx playwright install chromium
npm run test:browser
```

Скрипт сам поднимает локальный сервер и закрывает его. `BROWSER_CHANNEL=msedge` переключает на установленный Edge, `PLAYWRIGHT_MODULE` — на существующую установку Playwright. Проверяются переходы, история, восстановление в чистом профиле, повреждённые данные, мобильная ширина 320/390/768/1440, Service Worker и офлайн-перезагрузка.

GitHub Actions выполняет unit-тесты и `check:sw` на каждый push и pull request; браузерный сценарий — отдельной задачей.

## Деплой

GitHub Pages, ветка `main`, корень репозитория. Сборки нет — публикуются файлы как есть.

При изменении любого файла из списка `FILES` в `sw.js` поднимите `vN` в `VERSION`: иначе вернувшиеся пользователи останутся на старом кэше. Это проверяет `npm run check:sw`. Новая версия активируется после закрытия старых вкладок приложения. Кэши других приложений на том же домене не удаляются.

Версия продукта (`vX.Y.Z` в подвале) обновляется отдельно — первой записью в `data/changelog.json`. Обе правки идут в одном коммите с релизом.
