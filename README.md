# Deadlock Challenge Roulette

Фан-генератор челленджей для Deadlock: рулетка, случайный билд, запрет, свой набор, история. Чистые HTML/CSS/JS (ES modules), без сборки и бэкенда.
> Фан-проект, не связан с Valve. Deadlock — торговая марка Valve.

## Деплой на GitHub Pages
1. Загрузите файлы проекта в корень репозитория. 2. Settings → Pages → Source: *Deploy from a branch* → `main` / `/ (root)`. 3. Откройте `https://<user>.github.io/<repo>/`.
Локально: `python3 -m http.server` (ES modules и fetch не работают с `file://`).

## Структура
`index.html`, `css/style.css`, `js/{rng,state,storage,i18n,roulette,builds,share,validation,ui}.js`, `data/{heroes,items,challenges,i18n}.json`, `assets/`, `manifest.json`, `sw.js`, `tests/`.

## Данные и точность
Данные не сверены с API (сеть была недоступна). Всё, что не подтверждено, помечено `"verified": false` — это **список героев** и **предметы** (только T1/T2). Способности у героев хранятся как слоты 1–4 без выдуманных названий.
**Обновление после патча:** сверьте данные с доступным источником игры, например `https://assets.deadlock-api.com` (heroes/items). Сохраняйте стабильные строковые `id` приложения для совместимости истории; внешний ID можно хранить отдельным полем. Проверяйте также цены, ветки и уровни предметов. Ставьте `"verified": true` только после проверки и записывайте источник/дату в данных. Во время исправлений 14 ноября 2026 этот API был недоступен: каталог остаётся демонстрационным, о чём сообщает интерфейс.

При **любом** изменении кода или данных поднимайте суффикс версии `VERSION` в `sw.js`. Код и JSON кэшируются вместе как один выпуск. Новая версия активируется после закрытия старых вкладок приложения; затем откройте приложение заново. Кэши других приложений не удаляются. Старый общий кэш `dlr-v1` намеренно не удаляется автоматически: он мог использоваться другим приложением на том же домене.
Портреты не копируются в репозиторий: укажите URL в `icon`; при ошибке загрузки остаётся заглушка с инициалом.

## Как добавить челлендж
В `data/challenges.json` добавьте объект: `id`, `cat` (ab/it/gp/go/tm/ch), `difficulty` 1–5, `name{ru,en}`, `desc{ru,en}`, `tags`, `conflicts` (теги, с которыми он несовместим), `heroes` (`"all"` или массив id), `mult`, `mode` (`solo`/`team`).
Конфликт: A и B не выпадут вместе, если у одного в `conflicts` есть тег другого.

## Seed
Новые ссылки имеют формат `#v=2&seed=...&d=...&r=...&p=...&x=...`. В `x` сохраняются герой, условия и настройки генерации. Поэтому ссылка воспроизводит результат с замками и фильтрами, независимо от настроек получателя. Ссылки из истории и избранного используют тот же формат. Очки пересчитываются из текущего каталога; если сохранённые ID удалены, показывается ошибка, а не другой результат.

Старые ссылки `#seed=abc&d=mid&r=0&p=2` продолжают открываться с настройками по умолчанию. Из-за исправления генератора их исторический результат не гарантируется: старые ссылки не содержали достаточно информации. Записи локальной истории, содержащие героя и условия, переносятся в новый формат.

Число условий определяется отдельным потоком RNG, поэтому повторный бросок без замков и прямое восстановление совпадают. Пустые фильтры не отменяются автоматически. Неудачная генерация не расходует попытку. Локальные очки и результаты служат личной статистикой, а не защищённой таблицей соревнования.

## Проверки
Требуется Node.js 22 или новее. Сборка и установка пакетов для приложения и основных тестов не нужны:
```sh
node --test tests/core.test.js
```
Тесты проверяют 2000 комбинаций seed/сложности, ссылки с замками, фильтры, состояние, схемы данных и изоляцию кэшей. GitHub Actions выполняет их при push и pull request.

Дополнительная проверка в настоящем браузере:
```sh
npm install --no-save playwright
npx playwright install chromium
node tests/browser.mjs
```
Скрипт сам запускает локальный сервер и закрывает его после проверки. Можно задать `BROWSER_CHANNEL=msedge` для установленного Edge и `PLAYWRIGHT_MODULE` для существующей установки Playwright. Проверяются переходы, история, восстановление в чистом профиле, повреждённые данные, мобильная ширина, Service Worker и офлайн-перезагрузка.
