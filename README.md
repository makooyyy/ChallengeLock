# Deadlock Challenge Roulette

Фан-генератор челленджей для Deadlock: рулетка, случайный билд, запрет, свой набор, история. Чистые HTML/CSS/JS (ES modules), без сборки и бэкенда.
> Фан-проект, не связан с Valve. Deadlock — торговая марка Valve.

## Деплой на GitHub Pages
1. Загрузите файлы проекта в корень репозитория. 2. Settings → Pages → Source: *Deploy from a branch* → `main` / `/ (root)`. 3. Откройте `https://<user>.github.io/<repo>/`.
Локально: `python3 -m http.server` (ES modules и fetch не работают с `file://`).

## Структура
`index.html`, `css/style.css`, `js/{rng,state,storage,i18n,roulette,builds,share,validation,icons,ui}.js`, `data/{heroes,items,challenges,i18n}.json`, `assets/`, `manifest.json`, `sw.js`, `scripts/`, `tests/`.

## Интерфейс
Светлый фон, тёмная игровая панель и янтарные основные действия. Герой и условия показаны отдельными карточками; пустые условия после броска скрываются. Контракт содержит результат, таймер, избранное и экспорт. На телефоне навигация закреплена снизу, а кнопка генерации находится над результатом.

Настройки героев поддерживают поиск и сохраняют выбор скрытых поиском карточек. Дополнительные параметры звука и совместной игры раскрываются отдельно. В билдах показаны изображения, ветки, уровни, цены и активируемость предметов. Учитываются `prefers-reduced-motion`, фокус клавиатуры, состояния кнопок и RU/EN. Браузерные тесты проверяют все пять вкладок на ширинах 320, 390, 768 и 1440 px.

## Данные и точность
Каталог получен из [Deadlock API](https://deadlock-api.com/), версия клиента **6861**: **42 доступных героя и 156 предметов T1–T4**. Оба файла загружаются для одной зафиксированной версии через `/v1/assets/heroes` и `/v1/assets/items` на `https://api.deadlock-api.com`. Документация: https://api.deadlock-api.com/docs; схема: https://api.deadlock-api.com/openapi.json.

В `_meta` записаны версия клиента, дата получения, адрес запроса, SHA-256 ответа и общая ревизия каталога. `verified:true` означает соответствие полученному снимку API, а не независимую проверку Valve и не обещание вечной актуальности. Челленджи остаются авторскими правилами, их выполнимость API не проверяет.

В генерацию попадают только герои `player_selectable && !disabled && !in_development` и предметы `type=upgrade`, `shopable`, не отключённые, уровней 1–4. Служебные способности/оружие и специальные T5 исключены из обычных билдов. Сохраняются цены, ветки, уровни, активируемость, изображения и связи улучшений. Генератор не выдаёт одновременно предмет и его компонент, поэтому их стоимость не считается дважды. Это случайный набор конечных предметов; стоимость берётся из API, оптимизация промежуточных покупок не выполняется.

Внутренние строковые ID сохранены, API ID записаны в `apiId`. Например, `basic-magazine` теперь отображается как Extended Magazine. При следующих переименованиях сопоставление идёт прежде всего по API ID. Удалённые записи сохраняются как `active:false` для истории, но больше не выпадают.

### Обновление каталога
Требуется Node.js 22+ и доступ к публичному API; ключ не нужен:
```sh
node scripts/sync-catalog.mjs --check
node scripts/sync-catalog.mjs
node --test tests/*.test.js
```
Скрипт определяет последнюю версию клиента, получает оба каталога именно для неё, проверяет структуру, полноту, ID и граф компонентов. `--check` показывает изменения без записи. Ошибка API/валидации оставляет последний рабочий каталог; ошибки записи откатываются. Необычно большое сокращение каталога останавливает обновление для расследования. При отсутствии изменений файлы не переписываются. После успешного обновления публикуйте JSON и `sw.js` вместе.

Для воспроизводимой проверки скачанного снимка доступен `--input-dir DIR`: нужны `api-versions.json`, `api-heroes.json`, `api-items.json` и `snapshot.json` с `clientVersion`. Это режим доверенных локальных фикстур, не альтернативный источник игровых данных.

При изменении кода поднимайте версию выпуска (`v3`) в `sw.js`. При синхронизации данных скрипт автоматически меняет `CATALOG_VERSION`. Код и JSON кэшируются вместе как один выпуск. Новая версия активируется после закрытия старых вкладок приложения; затем откройте приложение заново. Кэши других приложений не удаляются. Старый общий кэш `dlr-v1` намеренно не удаляется автоматически: он мог использоваться другим приложением на том же домене.
Портреты не копируются в репозиторий: укажите URL в `icon`; при ошибке загрузки остаётся заглушка с инициалом.

## Как добавить челлендж
В `data/challenges.json` добавьте объект: `id`, `cat` (ab/it/gp/go/tm/ch), `difficulty` 1–5, `name{ru,en}`, `desc{ru,en}`, `tags`, `conflicts` (теги, с которыми он несовместим), `heroes` (`"all"` или массив id), `mult`, `mode` (`solo`/`team`).
Конфликт: A и B не выпадут вместе, если у одного в `conflicts` есть тег другого.

## Seed
Новые ссылки имеют формат `#v=2&seed=...&d=...&r=...&p=...&x=...`. В `x` сохраняются герой, условия и настройки генерации. Поэтому ссылка воспроизводит результат с замками и фильтрами, независимо от настроек получателя. Ссылки из истории и избранного используют тот же формат. Очки пересчитываются из текущего каталога; если сохранённые ID удалены, показывается ошибка, а не другой результат.

Старые ссылки `#seed=abc&d=mid&r=0&p=2` продолжают открываться с настройками по умолчанию. Из-за исправления генератора их исторический результат не гарантируется: старые ссылки не содержали достаточно информации. Записи локальной истории, содержащие героя и условия, переносятся в новый формат.

Число условий определяется отдельным потоком RNG, поэтому повторный бросок без замков и прямое восстановление совпадают. Пустые фильтры не отменяются автоматически. Неудачная генерация не расходует попытку. Локально сохраняются только результаты выполнения и провала.

## Проверки
Требуется Node.js 22 или новее. Сборка и установка пакетов для приложения и основных тестов не нужны:
```sh
node --test tests/*.test.js
```
Тесты проверяют 2000 комбинаций seed/сложности, ссылки с замками, фильтры, состояние, схемы данных и изоляцию кэшей. Дополнительно проверяются происхождение каталога, стабильность ID, исключение тестовых сущностей, повреждённые источники, циклы компонентов, смешанные версии и 500 билдов разных бюджетов. GitHub Actions выполняет их при push и pull request.

Дополнительная проверка в настоящем браузере:
```sh
npm install --no-save playwright
npx playwright install chromium
node tests/browser.mjs
```
Скрипт сам запускает локальный сервер и закрывает его после проверки. Можно задать `BROWSER_CHANNEL=msedge` для установленного Edge и `PLAYWRIGHT_MODULE` для существующей установки Playwright. Проверяются переходы, история, восстановление в чистом профиле, повреждённые данные, мобильная ширина, Service Worker и офлайн-перезагрузка.

### Темы и результаты
Светлая и тёмная темы переключаются кнопкой в шапке. При первом запуске используется системная тема, ручной выбор сохраняется. Выполнение и провал открывают карточку с героем, условиями и анимированной печатью; результат записывается один раз. Escape, кнопка закрытия и «Продолжить» закрывают карточку. При уменьшении движения в системе печать отображается без анимации.

### Режимы матчей
Перед генерацией можно выбрать Уличную стычку, Обычный или Рейтинговый режим. Добавлены 32 авторских задания: 12 для стычки, 8 для обычного режима и 12 для рейтингового. Старые задания доступны только в обычном режиме. В рейтинговом наборе нет запретов на способности и покупки. Режим сохраняется в настройках, истории, избранном и ссылках; старые ссылки считаются обычным режимом. Переключение режима очищает текущий контракт, сохраняя его в истории. Выполнение пользователь отмечает вручную.
Дизайн использует графитовую основу и фиолетовые акценты; печать успеха — фиолетовая.

### Сложность без очков
Очки, множители, редкость и ранги удалены. При загрузке старых сохранений эти поля отбрасываются; история и избранное сохраняются. Карточки результата и анимированные печати остаются.
Лёгкая: одно условие уровня 1. Обычная: одно условие до уровня 2. Сложная: два условия до уровня 4. Безумие: три условия до уровня 5. Проверены все 72 прежних задания; добавлены 8 простых альтернатив. Запреты на способности, ветки предметов, движение и покупки перенесены в сложную/безумную категории. Требования победы без смертей доступны только на «Безумии». Старые сохранённые контракты сохраняют свои условия и выбранную тогда сложность; новые ограничения применяются к новой генерации.

### Studio UI
Графитовая, белая и синяя палитра, компактная боковая навигация, карточки выбора режима в один ряд и крупные условия. Генерация расположена перед карточками, в пустом состоянии отображается только одно условие. На телефоне нижняя навигация остаётся доступной. Завершённый челлендж позволяет повторно открыть карточку с печатью без изменения статистики. Обе темы, клавиатурная навигация и уменьшение анимации сохранены.

### Build Lab и ограничения
Билды разделены на лайн (T1–T2, до 6 предметов), середину (T1–T3, до 8) и всю игру (T1–T4, до 12). Есть точный бюджет 800–100 000 душ, пресеты, герой, акцент ветки, лимит активных предметов и числа покупок. Это экспериментальный генератор, а не модель мета-синергии героя. Закрепления и отметки покупок сохраняются при пересборке, замена меняет только один незакреплённый и некупленный предмет. Цены полные, компоненты не дублируются с улучшениями. Бюджет расходуется по максимуму: генератор докупает и заменяет незакреплённые предметы, пока души помещаются в лимит этапа; свободный остаток появляется только там, где число предметов и максимальный тир уже не дают их потратить, и объясняется подсказкой под итогами. Сборка и настройки сохраняются локально; несовместимые с новым каталогом сохранения отклоняются.
Вкладка «Ограничение» объясняет добровольное правило на следующий матч. Можно выбрать героя, слот способности, исключить ультимейт из случайного выбора или запретить предмет из своего билда. Схема слотов показывает разрешённые и запрещённый слот; результат можно скопировать.
### Экспорт билда в Deadlock
Нажмите «Код для игры» в готовом билде: код копируется, затем открывается инструкция. В игре выберите героя и откройте Shop → Builds → Browse Builds → Create New Build → Paste, проверьте предметы и сохраните. Это код содержимого сборки, а не числовой ID для поиска. Если Paste отсутствует, нажмите Copy в игровом редакторе, затем повторно скопируйте код с сайта. При недоступном буфере код можно скопировать вручную.
Экспортируется показанная сборка целиком, включая купленные предметы, с порядком покупок. Закрепления и отметки покупок остаются на сайте. Сервер и Steam-авторизация для экспорта не нужны.
Формат: Base64(Zstandard(CMsgHeroBuild)), стандартные несжатые блоки Zstandard. Источники: [clipboard-код deadlock-plus](https://github.com/deadlock-plus/deadlock-plus/blob/main/crates/ring2/dp-builds/src/code.rs), [схема игрового protobuf](https://github.com/SteamTracking/Protobufs/blob/master/deadlock/citadel_gcmessages_common.proto), [RFC 8878](https://www.rfc-editor.org/rfc/rfc8878.html). Проверяются независимая распаковка, protobuf-поля, реальные ID, все герои и этапы, копирование и ручной резервный путь в браузере. Импорт проверен в запущенном Deadlock 2026-11-15 на Haze: билд на лайн (4 предмета) и полная сборка (12 предметов, 3 категории). Для совместимости передаётся ненулевой локальный ID-заглушка 1 (это не ID опубликованной сборки) и явные размеры категорий. Без ID игра сообщала об успешной вставке, но не загружала содержимое; без размеров предметы обрезались крошечным блоком. Сохранение/публикация тестового билда в самой игре не выполнялись.
### Челлендж вместе с билдом
При нажатии «Код для игры» экспортируется текущий показанный челлендж: герой задания, режим, сложность и полный текст всех условий на выбранном языке сайта. Текст включён в описание сборки и первой категории покупок; размер категории увеличен под инструкцию. В окне экспорта есть раскрываемый предпросмотр. Если герои билда и задания разные, показано предупреждение, исходные условия не меняются. При отсутствии текущего челленджа экспортируется только билд. Повторное копирование в открытом окне копирует тот же снимок; после нового броска откройте экспорт заново. Код и браузерный сценарий проверены автоматически; отображение новых текстовых описаний в клиенте игры отдельно не проверялось.
