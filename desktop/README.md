# ChallengeLock Desktop

Electron-обёртка над тем же статическим приложением. Код веба не дублируется: при сборке
папка проекта копируется в `web/`, и обёртка раздаёт её со своего локального сервера.

## Запуск и сборка

```bash
npm install
npm start        # запуск из исходников (берёт web-файлы из родительской папки)
npm run doctor   # проверка окружения, если приложение не открывается
npm run build    # NSIS-установщик в desktop/dist
```

> **PowerShell.** Если `npm` падает с «выполнение сценариев отключено в этой системе», это политика
> PowerShell, а не проект: он запускает `npm.ps1`. Либо вызывайте `npm.cmd` (`npm.cmd install`,
> `npm.cmd start`), либо разрешите локальные скрипты один раз без прав администратора:
> `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`.

`npm run build` собирает установщик и обновляет `latest.yml` для автообновления.
Публикация — workflow `.github/workflows/desktop-release.yml` по тегу `v*`.

## Почему фиксированный порт

Сервер слушает `127.0.0.1:47821`. Origin страницы — часть ключа, под которым Chromium
хранит `localStorage` и кэш Service Worker. Пока порт был случайным (`listen(0)`), каждый
запуск получал новый origin, а значит пустую историю, сброшенные настройки и заново
скачанный офлайн-кэш. Фиксированный порт делает origin стабильным и сохраняет данные
между запусками.

Если порт занят другим процессом, приложение откатывается на случайный: работать оно
будет, но этот запуск начнётся с чистого профиля (в консоль печатается предупреждение).

Данные профиля лежат в `%APPDATA%\ChallengeLock` (WebKit-хранилище Electron).

## Слежение за матчем

Приложение читает `console.log` игры и ловит переходы состояния: `ChangeGameState: GameInProgress (N)` — матч начался, `PostGame`/`GameOver`/`MatchEnd` — закончился. Когда матч завершается и есть незакрытый контракт, появляется диалог «Матч закончился. Засчитать контракт?» с кнопками **Выполнено / Провал / Позже**; выбор сразу закрывает контракт в приложении.

Детектор не зависит от догадок: он построен на реальном логе и на реальной последовательности состояний (`WaitingForPlayersToJoin → HeroSelection → MatchIntro → WaitForMapToLoad → PreGameWait → GameInProgress`). Если после начала матча встречается неизвестное состояние, оно пишется в `challenge-lock.log` строкой `unrecognised game state after GameInProgress: …` — по ней шаблон легко расширить.

Чтение идёт по смещению: файл не перечитывается целиком, а при перезапуске игры (лог обнуляется) смещение сбрасывается. Выигрыш или проигрыш из лога не выводятся — их выбирает игрок одной кнопкой.

## Пробник игры

В настройках приложения (блок «Игра и лог», только в десктопной сборке) есть кнопка «Найти игру». Она:

1. читает путь Steam из реестра (`HKCU\Software\Valve\Steam` → `SteamPath`);
2. разбирает `steamapps\libraryfolders.vdf` и обходит все библиотеки на всех дисках;
3. ищет `steamapps\common\Deadlock`, `Deadlock Beta` и `Project8Staging`;
4. находит `game\citadel\console.log` и показывает последние 40 строк.

Лог появляется, если добавить `-condebug` в параметры запуска Deadlock в Steam и зайти в матч. Пробник нужен, чтобы увидеть настоящий формат событий матча: по нему будет сделано автозакрытие контрактов, без догадок о содержимом лога.

## Если приложение не открывается

1. `npm run doctor` — проверяет Node, установленный Electron, его бинарник, файлы приложения и занятость порта 47821.
2. Если окно не появилось, откройте `%APPDATA%\challengelock-desktop\challenge-lock.log`: туда пишется вся последовательность запуска. Это важно на Windows — GUI-сборка Electron не выводит консоль в терминал, поэтому `npm start` выглядит как «ничего не произошло».
3. Если процесс жив, а окна нет, возможно, оно спрятано в трей: иконка может оказаться в «скрытых значках» рядом с часами.
4. Второй запуск больше не завершается молча: он показывает окно «Приложение уже запущено» и подсказывает, где искать окно.
5. Реальная ошибка запуска показывается системным окном с текстом исключения — его можно скопировать.
6. Если в логе есть `GPU process isn't usable. Goodbye.` — это падение GPU-процесса Electron, к приложению оно отношения не имеет. Оболочка запускается с программной отрисовкой (`app.disableHardwareAcceleration()`), потому что интерфейс двумерный; вернуть GPU можно флагом `--enable-gpu`. Остатки прошлых запусков лежат в `%APPDATA%\challengelock-desktop\GPUPersistentCache` — эту папку можно удалить.

## Трей и хоткеи

- `Ctrl+Alt+R` — новый челлендж, не выходя из игры: окно не забирает фокус, а результат ждёт вас, когда переключитесь.
- `Ctrl+Alt+O` — режим «поверх игры»: компактное окно 430×580 в правом верхнем углу, всегда сверху. Повторное нажатие возвращает прежние размеры и позицию.
- Закрытие окна прячет приложение в трей, а не завершает его — иначе хоткей перестал бы работать.
- Меню трея: показать/скрыть, новый челлендж, поверх игры, открыть папку данных, запускать с Windows, проверить обновления, о приложении, выход.
- «Запускать с Windows» регистрирует приложение в автозагрузке — работает только в собранной версии, в dev-режиме показывает пояснение.
- «О приложении» показывает версию, версии Electron и Chromium, порт, папку данных и путь к логу игры.
- Тултип трея показывает последний контракт, даже когда окно скрыто за игрой.

Если хоткей уже занят другой программой, приложение пишет об этом в консоль и работает дальше без него.

## Поведение

- Внешние ссылки открываются в системном браузере, а не в новом окне без адресной строки.
- Второй запуск не создаёт второй профиль: окно первого разворачивается.
- F5 или Ctrl+R перезагружают страницу, F12 открывает DevTools (меню приложения отключено).
- Автообновление — через `electron-updater`; веб-проверка релизов в обёртке отключена.
